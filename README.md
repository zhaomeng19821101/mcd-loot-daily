# 麦麦战报 mcd-loot-daily

> 基于**麦当劳中国官方 MCP Server**（`https://mcp.mcd.cn`）的每日情报 + 健康参谋：把活动日历、可领优惠券、卡包、积分、餐品营养数据一次拉全，生成「今天该抢什么、今天该吃什么」的每日报告。

**目标用户**：想每天花 30 秒知道"麦当劳今天有什么羊毛"的麦门人，以及想控制热量和钠摄入、但面对麦当劳复杂营养数据无从下手的健身/控盐人群。

## 关于本项目

- 本项目是 **[麦当劳程序员创意开发大赛](https://github.com/M-China/mcd-developer-innovation-challenge) 参赛作品**，非麦当劳官方产品，与麦当劳无隶属或背书关系。
- 使用的全部数据来自麦当劳**公开对外提供的 MCP Server**（接口文档见 [M-China/mcd-mcp-server](https://github.com/M-China/mcd-mcp-server)），未使用任何内部或非公开数据。
- 餐品价格、活动规则、营养成分均以麦当劳官方渠道实时结果为准；本项目输出仅供参考，不构成医疗、营养或其他专业建议。

## 解决什么问题

**情报侧**：麦当劳的优惠、活动、积分分散在 App 的多个角落，用户要自己逐个翻。

**健康侧**：想控热量或关注钠的人，面对 150+ 餐品的营养数据无从下手——哪些能点、哪些是陷阱热量、一个组合下来钠会不会超标。

本项目用 **6 个 MCP 工具**一次拉齐，输出两份结构化 Markdown 报告。

### 报告一：每日战报（`report/战报-YYYY-MM-DD.md`）

- **今日可抢**：麦麦省里状态为"可领取"的新券，已领取的折叠隐藏
- **今天在搞什么**：当日营销活动日历（新品、联名、抽奖预约）
- **积分**：可用 / 累计 / 冻结 / 已过期 / 本月将过期
- **卡包**：已持有的券清单，**今日到期的排在最前并单独高亮**

### 报告二：健康参谋（`report/健康参谋.md`）

- **热量预算搭配**：给定目标热量（如 800 kcal），推荐 3 套接近预算且尽量吃饱的组合，同等饱腹度下优先低钠，3 套主食不重复
- **钠含量洞察**：低钠优选榜（≤60mg）+ 高钠警示榜（≥每日推荐量一半），含"约合食盐"换算
- **高蛋白优选榜**：按「蛋白/热量」比值排序
- **全量分类健康表**：按 汉堡/麦满分、鸡肉炸物、小食薯条、饮品咖啡 分类，热量升序，含热量、蛋白质、脂肪、碳水、钠五项

## 几个有意思的真实发现

数据来自 `list-nutrition-foods` 实测（154 条有效餐品）：

**钠才是麦当劳真正的隐藏成本。** 成年人每日钠推荐摄入约 2000mg，而：

| 餐品 | 钠(mg) | 约合食盐 | 占每日推荐 |
|---|---:|---:|---:|
| 芝士双层安格斯厚牛堡 | 1373 | 3.4g | **69%** |
| 培根双层安格斯厚牛堡 | 1191 | 3.0g | 60% |
| 板烧鸡腿堡 | 1041 | 2.6g | 52% |
| 大杯玉米杯 | **2** | ~0 | ~0% |
| 100%苹果汁 | **0** | 0 | 0% |

一份厚牛堡的钠就吃掉全天推荐量的一半以上，而换成玉米杯或苹果汁基本为零——**饮品和小食是控钠的关键杠杆**，比纠结汉堡本身有效得多。

**汉堡的热量跨度是 250~1000 kcal。** 从烟肉蛋麦满分（260）到芝士双层安格斯厚牛堡（1003），同一份菜单里差了近 4 倍。选择比自律更重要。

## 安装

### 1. 配置麦当劳 MCP

到 [麦当劳 MCP 开放平台](https://open.mcd.cn/mcp) 手机号登录并申请 MCP Token，然后在 WorkBuddy 中：

**左侧边栏 → 专家·技能·连接器 → 连接器 → 右上角【自定义连接器】→【配置 MCP】**，粘贴（替换占位符）：

```json
{
  "mcpServers": {
    "mcd-mcp": {
      "type": "streamablehttp",
      "url": "https://mcp.mcd.cn",
      "headers": {
        "Authorization": "Bearer 你的MCP_TOKEN"
      }
    }
  }
}
```

保存后回到【自定义连接器】，将 `mcd-mcp` **启用**。脱敏模板见 [mcp-config.example.json](./mcp-config.example.json)。

> 限流：每个 Token 每分钟最多 600 次请求，超出返回 429。请妥善保管 Token，不要提交到仓库。

### 2. 安装 Skill

把本仓库的 `mcd-loot-daily/` 目录（含 `SKILL.md`）放入 WorkBuddy 的技能目录（用户级 `~/.workbuddy/skills/` 或项目级 `.workbuddy/skills/`），重启 WorkBuddy 后生效。

### 3. 环境要求

- Python 3.8+（仅用标准库，无第三方依赖）

```bash

# 指定输出目录
python scripts/nutrition.py --all --outdir report
```

## 工程实现要点

**MCP 返回格式实测有四种**，脚本为每种写了独立解析器：

| 数据 | 格式 |
|---|---|
| 时间 / 积分 | 标准 JSON |
| 活动日历 / 可领券 | Markdown 列表 |
| 卡包 | `## 标题` + `**标签**` 块 |
| 营养数据 | 自定义扁平格式 `[160]{字段,...}:` + CSV 行 |

**数据清洗**（营养侧实测踩过的坑）：

- **名称去重**：`list-nutrition-foods` 返回 160 条中有 2 条完全重复，按「名称 + 四项营养素」去重
- **脏名称过滤**：上游对部分商品名做了安全词过滤，返回 `yeyeyeye奶冻款`、`“苹板”支撑Pro` 这类名称。脚本识别并跳过，在报告开头注明跳过数量，**不删改营养数据、不静默丢弃**
- **列错位防御**：部分行有描述文本导致逗号数不一致，采用「从右往左定长取 7 个数值」策略解析
- **儿童餐隔离**：大预算场景自动排除儿童餐，避免拿儿童餐的钠基准评价成人
- **份量口径提示**：麦当劳营养数据中汉堡是单份、薯条有中/大/小、麦旋风是常规，跨品类比较仅作量级参考，报告中已标注

## 已知限制（如实说明）

**卡包里的券无法参与比价计算。** 实测确认：

- `calculate-price` 要求传 `couponId` + `couponCode`（传券参数返回 `600010: 使用优惠券需要couponId和couponCode`）
- 而 `query-my-coupons` 只返回人类可读信息（标题 / 金额 / 有效期 / 标签），**不含券 ID，也不含商品编码**
- 两者没有共同的匹配键，且券名与菜单 `name` 写法不一致

因此本项目承诺的是「**菜单折扣率最优**」（基于 `query-meals` 的现价 / 原价，实测最高 57.3% off），而**不是**「帮你用券最省」。这个限制在 SKILL.md 里也写明了，避免 Agent 给出做不到的承诺。

## 合规与红线

- **不会**自动执行领券、下单、抽奖等写操作；用户明确要求时才执行并先复述确认。
- 不采集、不存储 Token、手机号、地址等敏感信息；配置仅用环境变量占位符。
- 报告数据全部来自麦当劳 MCP 实时返回；某板块拉取失败时如实标注，不编造。
- 健康建议标注为非专业建议；钠→食盐换算标注为粗略估算。
- 餐品、价格、活动以麦当劳官方渠道实时结果为准。
