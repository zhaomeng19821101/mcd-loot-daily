# 麦当劳每日战报（mcd-loot-daily）

## 这个 Skill 解决什么问题

麦当劳的优惠券、营销活动、积分有效期分散在 4 个不同的地方，用户要自己翻 App 才知道"今天到底有什么值得抢"。这个 Skill 把它们一次拉全，交叉比对，输出一份可以直接照着做的战报。

## 前置条件

已配置麦当劳 MCP 连接器 `mcd-mcp`（见仓库根目录 `mcp-config.example.json`），且已在 WorkBuddy 的「专家·技能·连接器 → 连接器 → 自定义连接器」中**启用**。
Token 通过环境变量 `MCD_MCP_TOKEN` 提供，**不要**写进任何仓库文件。

## 执行步骤

### 1. 并行拉取 5 份原始数据

一次性调用以下 MCP 工具，不要串行等待：

| 工具 | 用途 |
|---|---|
| `now-time-info` | 拿当前服务器时间，作为战报的日期基准 |
| `campaign-calendar` | 当月营销活动（不传 `specifiedDate` 拿全月） |
| `available-coupons` | 麦麦省里**可领取**的券 |
| `query-my-coupons` | 卡包里**已拥有**的券（`page=1`, `pageSize=200`） |
| `query-my-account` | 积分余额、冻结、即将过期 |

### 2. 把原始返回落盘

将每份工具返回的 JSON 分别写入 `data/` 目录，文件名固定：

```
data/time.json
data/calendar.json
data/available.json
data/mine.json
data/account.json
```

只保留工具返回的 JSON 本体，去掉说明性文字。**若某份数据拉取失败，写入 `{"__error": "<原因>"}` 占位**，脚本会跳过它并在战报中标注"该板块本次未获取"，不要因为一个工具失败就中断整份战报。

### 3. 生成战报

在项目根目录运行：

```bash
python scripts/build_report.py --date auto
```

脚本会读取 `data/*.json`，输出 `report/战报-<日期>.md`。

### 4. 交付

把生成的战报全文呈现给用户。如果 `data/` 里某个文件是 `__error` 占位，如实说明该板块没拉到，**不要编造数据填补**。

...

## 红线

- **不要**自动执行 `auto-bind-coupons`（一键领券）、`create-order`、`mall-create-order`、`draw-lottery` 这类会消耗积分或产生订单的写操作。用户明确要求时才执行，并且执行前复述一遍将要发生的事。
- **不要**把 Token、Cookie、手机号、地址等信息写进 `data/` 或战报正文。
- 积分、券的口径以 MCP 实时返回为准，不要用缓存值回答"现在有多少分"。
