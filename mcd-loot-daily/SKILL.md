# 麦当劳每日情报与健康参谋（mcd-loot-daily）

## 这个 Skill 解决什么问题

**情报侧**：麦当劳的优惠券、营销活动、积分有效期分散在多个地方，用户要自己翻 App 才知道"今天到底有什么值得抢"。

**健康侧**：想控制热量或关注钠摄入的人，面对麦当劳复杂的营养数据无从下手——哪些能点、哪些是陷阱热量、一个组合下来钠会不会超标。

本 Skill 把这两件事一次拉齐，交叉比对后输出可直接照着做的报告。

## 前置条件

已配置麦当劳 MCP 连接器 `mcd-mcp`（见仓库根目录 `mcp-config.example.json`），且已在 WorkBuddy 的「专家·技能·连接器 → 连接器 → 自定义连接器」中**启用**。
Token 通过环境变量 `MCD_MCP_TOKEN` 提供，**不要**写进任何仓库文件。

## 执行步骤

### 1. 并行拉取原始数据

一次性调用以下 MCP 工具，不要串行等待：

| 工具 | 用途 | 数据文件 |
|---|---|---|
| `now-time-info` | 当前服务器时间，作为报告日期基准 | `data/time.json` |
| `campaign-calendar` | 当月营销活动（不传 `specifiedDate` 拿全月） | `data/calendar.json` |
| `available-coupons` | 麦麦省里**可领取**的券 | `data/available.json` |
| `query-my-coupons` | 卡包里**已拥有**的券（`page=1`, `pageSize=200`） | `data/mine.json` |
| `query-my-account` | 积分余额、冻结、即将过期 | `data/account.json` |
| `list-nutrition-foods` | 全量餐品营养数据（热量/蛋白/脂肪/碳水/钠/钙） | `data/nutrition.json` |

用户只问健康问题时可跳过前 5 个；只问战报时可跳过 `list-nutrition-foods`。

### 2. 把原始返回落盘

**只保留工具返回的 JSON 本体**，去掉说明性文字。`list-nutrition-foods` 的返回需保留
`data` 字段里的扁平文本原样（形如 `[160]{productName,...}:` 后跟数据行），不要手工转成表格。

**若某份数据拉取失败，写入 `{"__error": "<原因>"}` 占位**，脚本会跳过该板块并在报告中如实标注
"本次未获取"，不要因为一个工具失败就中断整份报告。

### 3. 生成战报（情报部分）

```bash
python scripts/build_report.py --date auto
```

输出 `report/战报-<日期>.md`。

### 4. 生成健康参谋（健康部分）

```bash
python scripts/nutrition.py --budget 800          # 按热量预算推荐三件套
python scripts/nutrition.py --low-sodium           # 钠含量洞察
python scripts/nutrition.py --protein             # 高蛋白优选榜
python scripts/nutrition.py --table                # 全量分类健康表
python scripts/nutrition.py --all                  # 全部板块
```

输出 `report/健康参谋.md`。

常用参数：
- `--budget N` — 热量预算（kcal）。脚本会推荐 3 套**接近预算且尽量吃饱**的组合，
  同等饱腹度下优先低钠，且保证 3 套主食不重复。预算 ≥600 时自动排除儿童餐。
- 其他参数均为开关，不带参数时等价于 `--all`。

### 5. 交付

把生成的报告全文呈现给用户。如果某个文件是 `__error` 占位，如实说明该板块没拉到，
**不要编造数据填补**。

## 红线

- **不要**自动执行 `auto-bind-coupons`（一键领券）、`create-order`、`mall-create-order`、`draw-lottery` 这类会消耗积分或产生订单的写操作。用户明确要求时才执行，并且执行前复述一遍将要发生的事。
- **不要**把 Token、Cookie、手机号、地址等信息写进 `data/` 或报告正文。
- 积分、券、营养的口径以 MCP 实时返回为准，不要用缓存值回答"现在有多少分""这个多少热量"。
- **健康建议要标注为非专业建议**，不要给出减重、控糖等医疗性质的承诺。钠→食盐换算是粗略估算，必须在输出中说明。
- 上游接口对部分商品名做了安全词过滤，返回的 `yeyeyeyeXX`、`“XX”XX` 形式名称不可直接展示给用户。脚本已自动跳过并在报告开头注明，不要手动把脏名称写进输出。

## 已知限制（如实告知用户，不要回避）

**卡包里的券无法参与比价计算。** 原因：
- `calculate-price` 要求传 `couponId` + `couponCode`（实测返回 `600010`）
- 而 `query-my-coupons` 只返回人类可读信息（标题/金额/有效期/标签），**不含券 ID 和商品编码**
- 两者没有共同的匹配键，标题写法也与菜单 `name` 不一致

所以本 Skill 承诺的是"**菜单折扣率最优**"（基于 `query-meals` 的现价/原价），
**不是**"帮你用券最省"。被问到用券省多少钱时，如实说明这个限制。
